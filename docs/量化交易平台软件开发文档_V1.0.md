# 基于论文复现的量化交易平台软件开发文档

版本 V1.0　日期 2026年10月23日　适用阶段 课程项目设计与开发

本文面向项目开发者、课程指导教师及答辩评审，规定一个以论文复现为核心的量化交易教学平台。平台由模拟交易前台、可视化研究后台和共享实验引擎组成，完整呈现数据处理、模型训练、策略生成、历史回测和模拟交易过程。首期实现两条独立论文方法，并通过统一的实验记录和策略接口支持后续增加论文。

项目的核心交付是可运行、可观察、可重复的研究与交易闭环。模型效果以实际实验为准，不以达到论文中的某个收益率作为软件验收条件。首期采用本地历史数据和历史行情回放，不接真实券商账户。

## 1 项目目标与范围

### 1.1 项目定位

平台首先服务于课程作业中的论文复现，其次提供可操作的模拟交易体验。后台需要让使用者看懂每一步的输入、处理、输出和论文依据；前台需要让使用者看懂当前持仓、模型判断、订单执行及收益变化。两端共享版本化的数据和模型，不能各自维护一套无法对应的结果。

第一条研究路线复现孙宏鑫、魏先华的趋势学习混合神经网络：原始价格进入 CNN，历史局部趋势进入 LSTM，两路特征融合，分别预测下一趋势的方向和持续时间，再据此构建多空策略。[P1，PDF第4至9页]

第二条研究路线复现龚雅键等人的随机性多目标强类型遗传规划：构建带类型的表达式树，通过随机多目标适应度与滚动窗口进化出交易规则，原论文信号对应做多或空仓。[P2，PDF第4至11页]

### 1.2 首期交付边界

| 优先级 | 交付内容 | 完成标准 |
| --- | --- | --- |
| P0 必须 | 数据导入与质量检查 | 支持本地 CSV，形成不可变数据版本 |
| P0 必须 | CNN LSTM 混合模型复现 | 两路输入、特征融合、方向与时长两个训练任务 |
| P0 必须 | STGP RMO Rolling 复现 | 类型约束、按代随机权重、滚动训练与样本外信号 |
| P0 必须 | 训练和进化过程可视化 | 显示真实指标、激活或表达式树，并能回放 |
| P0 必须 | 历史回测与模拟交易 | 共用成交与记账引擎，支持手动和策略驱动 |
| P0 必须 | 实验报告与依据追溯 | 从订单追溯到策略、模型、实验、数据及论文 |

当前不纳入真实交易、自动资金划转、高频撮合、分布式训练集群和任意 Python 在线执行。扩展性通过模块接口和版本化配置实现，首期不建设通用低代码算法平台。

## 3 角色与使用流程

### 3.1 角色

研究者负责导入数据、创建实验、训练模型、解释结果及发布策略版本。模拟交易者负责选择已发布策略、回放行情、手动下单和查看决策。教师或评审以只读方式查看实验过程、复现配置、模型对照和报告。单人部署可由同一账号切换研究与交易工作区。

### 3.2 端到端闭环

研究流程为：选择论文模板 → 选择数据版本 → 检查质量 → 配置预处理与时间切分 → 预览样本 → 执行训练或进化 → 查看解释与对照 → 回测 → 保存报告 → 发布策略版本。

交易流程为：创建虚拟账户 → 选择历史区间和策略 → 回放推进 → 在已可用信息上推理 → 生成目标仓位 → 风控检查 → 下一个允许成交的行情点撮合 → 更新账户 → 查看交易依据。

系统必须允许只完成某一步进行教学演示，例如只查看趋势分段、只播放卷积计算、只观察第8代策略树。步骤页面相互衔接，但不能伪装成每一步都在独立优化一个模型。

### 3.3 三种运行方式

| 方式 | 数据与用途 | 状态要求 |
| --- | --- | --- |
| 真实训练 | 用所选数据重新训练网络或进化规则 | 实时状态、日志、检查点及结果来自任务进程 |
| 实验回放 | 读取一次已完成实验的指标与中间快照 | 显示原实验时间及回放位置 |
| 教学示例 | 用小数据和样例模型解释计算 | 始终标明示例，不能生成正式研究结论 |

## 4 系统结构与技术方案

### 4.1 总体结构

浏览器包含研究工作区与交易工作区；两者通过同一个 API 服务访问数据、实验、策略和账户。训练进程与回放进程在服务端执行，事件流将任务状态和采样结果发送给浏览器。元数据保存到关系数据库，行情、权重及大张量保存为文件，数据库只保存引用和校验值。

逻辑链路为：浏览器 → API 与鉴权 → 实验调度或交易会话 → 方法插件及共享回测引擎 → 数据库与产物文件。训练进程只能写实验产物，交易进程通过策略发布版本读取模型，避免训练中的权重直接影响账户。

### 4.2 推荐实现

| 层次 | 首期建议 | 选择目的 |
| --- | --- | --- |
| 前端 | React、TypeScript、Vite，图表使用 ECharts，计算演示使用 Canvas 或 SVG | 支持复杂交互、时间轴和张量观察 |
| 服务端 | Python、FastAPI、Pydantic | 统一算法接口、校验配置并提供事件流 |
| 神经网络 | PyTorch | 获取中间激活并实现可观察的训练循环 |
| 遗传规划 | DEAP 加强类型约束与自定义适应度 | 复用树生成与进化能力，补齐论文逻辑 |
| 数据处理 | pandas、NumPy、Parquet | 处理时序、快照和实验数据 |
| 存储与任务 | SQLite、本地文件、独立 worker 进程及持久化任务表 | 便于本地交付，训练不阻塞 API |
| 部署 | 本地启动脚本；可选 Docker Compose | 适合课程演示与后续迁移 |

P1原文使用 Keras，课程实现建议使用 PyTorch；框架改变属于工程适配，必须记录权重初始化、激活函数、优化器参数和数值精度等差异。首期不要求与原 Keras 权重互通。

SSE用于单向任务事件推送，控制命令通过普通 HTTP 请求提交。断线后按事件序号补读。SQLite只承担单机少量并发写入；需要多人同时训练时再替换为 PostgreSQL 和独立队列，保留服务接口。

### 4.3 建议目录与模块职责

frontend 保存两个工作区及公共可视化组件；backend 保存 API、鉴权和配置校验；research 保存数据管线、论文方法、指标和实验编排；trading 保存信号适配、撮合、记账和风险控制；storage 保存版本记录及文件存取；tests 保存时序、算法、交易与端到端测试；docs 保存本开发文档、论文映射和实验说明。

方法代码不得直接操作浏览器或账户表。前端不得自行算正式收益和替代后端预测；前端局部计算只用于显示和交互。

## 5 数据管理与时间一致性

### 5.1 首期数据集

P1使用沪深300股指期货5分钟收盘价，整体实验数据跨度为2013年至2018年；预测性能实验使用2015至2017年数据。P2核心股票指数实验使用日频沪深300及上证指数环境因子，并包含上证50、中证500和IF期货扩展实验。[P1第5至8页；P2第8至9、14页]

首期先支持用户本地导入历史数据。需要准备IF五分钟数据、IF日线或可构建日线的数据、沪深300日线及上证指数日线。P2指标包含120日均线，125日训练窗之前仍需额外准备指标预热数据。训练窗口长度不等于原始文件所需长度。

| 数据对象 | 必需字段 | 约束 |
| --- | --- | --- |
| 行情条目 | symbol、timestamp、frequency、close、source | 时间可解析，同标的同频率时间唯一，价格为有限正数 |
| 日频扩展 | open、high、low、volume | 依赖指标或下一开盘成交模式时必须存在 |
| 合约资料 | contract_id、有效区间、交易日历、乘数、保证金率、手续费表 | 必须版本化，缺失时不能启用相应仿真模式 |
| 数据清单 | 文件哈希、行数、时间范围、时区、字段映射、处理版本 | 一经实验引用不可覆盖 |

### 5.2 数据质量与换月

导入后检查重复、乱序、缺失区间、异常值、非交易时段、跨频率冲突和成交量缺失。默认不填充缺失价格产生虚构交易；允许明确的研究填补配置，报告必须列出范围。时间统一按 Asia/Shanghai 显示，按交易日历推进，不把午休、夜间和节假日当成有效五分钟交易条目。

主连或复权序列可用于研究，但不能把换月拼接跳变直接记成可成交盈利。期货仿真应按真实合约执行，在换月点平旧开新并计费；只有连续序列而没有实际合约映射时，限定为研究收益回放，并在报告说明不能等同真实合约账户。

### 5.3 防止使用未来信息

每个样本保存 feature_start、feature_end、label_start、label_end、available_at 和 partition。推理只能读取 available_at 不晚于当前回放时间的数据。特征变换拟合、阈值选择和超参数选择均限制在训练或验证区间，最终测试区间只用于报告。

趋势分段是重点审计项。离线全样本分段可以用于构造研究标签和观察真实趋势，但不能自动当作在历史时刻已经知道的特征。严格交易模式在每个决策时刻仅对可见历史前缀分段；段终点的确认可能滞后，必须保存确认时刻和历史快照，不能用后来修订的段端点回写旧决策。

切分按时间进行。跨越训练与验证或测试边界的标签样本要剔除；存在重叠预测区间时进一步清除跨界重叠。训练内 shuffle=True 仅表示样本顺序打乱，不能改变外部时间切分。研究模式若保留原论文不充分明确的离线构造方法，要单独报告与严格时间可用性模式的差异。

## 6 论文一复现管线

### 6.1 步骤与产物

| 步骤 | 输入与处理 | 后台输出 | 依据 |
| --- | --- | --- | --- |
| A1 趋势提取 | 五分钟收盘价，自上而下分段线性表示 | 原曲线、分段线、边界、误差及每段斜率时长 | P1第4至5页 |
| A2 双路样本 | 连续4段趋势；每段结束点回看5个收盘价 | CNN的4×5矩阵，LSTM的4×2矩阵，下一段标签 | P1第5至6页 |
| A3 数值处理 | CNN矩阵各元素减去首行首列价格 | 处理前后数值对照及样本索引 | P1第6页图2 |
| A4 基线训练 | 单CNN和单LSTM分别训练方向、时长任务 | 独立模型与训练曲线 | P1第6至8页 |
| A5 混合训练 | 两路特征映射到同维度后相加，经输出层预测 | 两个混合模型及真实层输出 | P1第4至5页 |
| A6 评估回测 | 方向、时长预测及持仓规则 | 分类指标、时长误差、交易日志和资金曲线 | P1第7至11页 |

分段实现需声明拟合误差度量、停止阈值、最短段长、端点归属和平坦趋势处理。默认平坦段单列统计，分类时并入非上涨类；这属于实现约定。以差值除以段内点数计算论文口径斜率，同时保留点数、条目间隔和实际时间，防止分母差一问题。

### 6.2 正确的网络关系

CNN与LSTM是并联分支。CNN输入来自历史价格矩阵，LSTM输入来自历史趋势的斜率和持续时间；分支输出经过可训练映射进入同一特征空间，相加后通过全连接输出层预测。默认融合类型为 add_projected，不以拼接或投票替代论文融合方式。

后台可以按“看卷积 → 看记忆 → 看融合”的顺序讲解，但混合模型通过最终损失反向传播，联合更新CNN、LSTM和融合层。CNN与LSTM单独训练是基线实验，不是混合模型训练必须依赖的预训练步骤。

论文分别讨论方向分类与时长回归。首期按两个独立训练任务实现，每个任务都可选择CNN、LSTM或混合结构，总计六类基础实验。共享主干的双输出多任务模型作为后续扩展，不能默认声称属于原论文。

### 6.3 参数与轴定义

| 参数 | 论文核实值或首期约定 | 可否调整 |
| --- | --- | --- |
| 历史趋势数、局部价格数 | 4、5，论文设置 | 探索实验可调整 |
| CNN形状 | 业务视图4×5；按原Keras Conv1D语义暂定步长轴4、通道轴5 | 必须保存 axis_mapping |
| PyTorch输入 | 价格张量转为批次×5×4；LSTM为批次×4×2 | 转置不得默默改变卷积语义 |
| CNN层数、通道、卷积核 | 两层、20、1，论文设置 | 探索实验可调整 |
| LSTM隐藏单元 | 100，论文设置 | 探索实验可调整 |
| 优化器、学习率、批大小、轮数 | Adagrad、0.005、128、65，论文设置 | 均可配置并存档 |
| Dropout和L2 | 论文明确使用，但具体系数未充分交代 | 课程默认0.2和0.0001，标记补充约定 |
| 激活、池化与融合维度 | 待代码核验项；课程暂用ReLU、池化核1、融合维度100 | 池化核1为恒等操作，明确列为差异 |
| 方向与时长损失 | 二分类交叉熵与RMSE，加L2正则 | 分别记录主损失与正则项 |
| 样本顺序 | 支持False与True对照；交易配置默认False | 不影响时间切分 |

卷积核1的真实含义是对每个位置的通道做变换，不是在相邻价格点间以3点核滑动。教学动画应忠于当前轴和核大小；用户在探索模式改成3点核时，结构图、输出形状和论文差异列表同时更新。论文关于局部价格窗口的公式与文字计数需以“每段5个价格点”的实验描述实现，并在样本预览中明确包含哪些时刻。

### 6.4 方向与时长评估

方向输出为上涨概率，内部1代表上涨。阈值默认0.5；复现阈值搜索采用0至0.9、步长0.05及Fβ指标，β=0.4，但搜索只在验证集进行。报告同时给出固定阈值与验证集选定阈值下的Accuracy、Precision、Recall、Fβ和混淆矩阵。

时长回归以小时为论文展示单位，同时保存可执行的有效行情条目数。RMSE用于与论文比较，MAE作为平台补充。模型原始预测必须保存；用于交易的时长另做正值、上限及交易日历映射，记录修正值与原因。跨休市的小时含义原文不够清晰，默认交易时长按有效条目计数，报告同时列出墙上时钟跨度。

训练阶段必须展示训练集与验证集曲线。早停作为探索开关，论文配置默认跑满65轮；最终测试只在模型和阈值冻结后运行。

### 6.5 滚动交易复现

按论文设置建立2013至2015训练后测2016、2014至2016训练后测2017、2015至2017训练后测2018三个年度实验。每段预测的时长到期后，只纳入已经出现的数据，重新提取历史趋势并生成下一次预测。[P1第8至9页]

原文循环步骤对是否每次重新训练的描述不够清晰。平台同时提供 fixed_model_update_features 和 refit_each_segment 两种显式配置，默认先实现前者以保证演示可运行，报告标为实现解释；后者用于完整差异实验。不得在后台显示每段重新训练而实际上复用同一权重。

策略按预测方向做多或做空，同向维持，反向先平后开。止损按持仓方向计算入场以来的不利收益，阈值默认负0.6%；触发后在该预测段剩余时间保持空仓。手数默认1，成交时间规则遵循第10章。论文中“无杠杆”口径以名义本金收益研究模式表达，仿真账户另按合约保证金与现金记账。

## 7 论文二复现管线

### 7.1 特征与表达式树

使用日频数据构造30个终端因子：P1至P5价格滞后、MA5/10/20/60/120均线、V1至V5成交量滞后、MV5/10/20/60/120成交量均线、SD5/10/20/60/120波动率、dM1至dM5上证指数涨跌幅滞后。[P2第9页表3]

价格和量按论文以2015年1月5日相应基准值缩放。基准值缺失时不允许静默改用其他日期；使用其他期间的数据必须选择替代基准并标为探索实验。波动率的收益定义和标准差口径、均线是否包含当前条目，在因子规范中明确；按特征可用时间做最终滞后对齐，避免信号对应日错位。

| 运算组 | 输入与输出类型 | 约束 |
| --- | --- | --- |
| 加减乘除、Max、Min | float与float到float | 除零和非有限值必须受控 |
| 大于、小于 | float与float到bool | 根节点最终输出bool |
| And、Or、Not | bool到bool | 禁止把bool当float参与算术 |
| if_then_else | bool、float、float到float | 交叉与变异后重新校验 |
| isBetween | 三个float到bool | 端点次序和是否含等号作为实现约定固定 |

允许的常量集合及随机常量生成规则要登记为补充约定。表达式以带类型的AST保存并通过白名单解释器执行，不接受用户上传字符串后直接执行。除零默认返回指定有限值并计数；过多异常的个体判为无效，避免靠数值异常取得高适应度。

### 7.2 多目标适应度

三个原始目标为收益回撤比RefDown、夏普比率Sharpe和方向信号正确率Accu。依P2第11页式3.1至3.3，将可比指标定义为：a取RefDown；b取Sharpe减1后除以0.5；c取Accu减0.50后除以0.015。这里Accu使用0至1小数。

FMO为a、b、c分别乘以1/3后相加；PRMO为a、b、c分别乘以r1、r2、r3后相加；RMO为a、b、c分别乘以1/3+r1、1/3+r2、1/3+r3后相加。默认每代独立抽取三个U(0,1/3)随机数，并在该代全部候选个体之间共享，固定随机种子且完整存档。

每代权重变化后，要以本代权重重新计算父代、子代和精英候选的分数；不能复用上一代总分。可以缓存每棵树的三个原始指标，再进行当代加权。跨代总分不能直接作为固定尺度比较，界面同时展示原始指标、当代权重和标准化指标。最终候选默认按最后一代同权重评估结果选出，最终树不因测试收益而更换。

零波动、零回撤、无交易和全上涨或全下跌个体需要单列标识。平台不把无穷大当成最优分数；分母为零的适应度默认使用可配置的有限下界和有效性判定，并在报告登记。这属于数值实现约定。

### 7.3 进化与滚动参数

| 参数 | 论文配置 | 后台观察内容 |
| --- | --- | --- |
| 种群与代数 | 100、20 | 每代个体数、最优及分布 |
| 进化类型 | μ+λ | 父代与子代共同参与选择 |
| 初始化 | Ramped half and half，初始深度2至4 | 初始树形和类型分布 |
| 深度与生长 | 最大深度15，生长深度0至1 | 超深个体数与拒绝原因 |
| 交叉与变异 | 概率0.7与0.2，单点交叉、均匀变异 | 操作前后树和替换子树 |
| 滚动窗口 | 训练125交易日，预测20交易日 | 当前训练段、预测段和历史窗口 |
| 交易信号 | True做多、False空仓 | 仓位变化及信号一致性 |

以上参数依据P2第8页表2及2.6节。λ大小、选择算子及锦标赛规模等未完整说明，暂定λ=100、锦标赛规模3，记录为实现约定；不是论文参数。繁殖算子的概率实现方式要固定，不能把0.7和0.2混用为互斥和独立两种规则。首期采用互斥采样，剩余0.1为复制。

每个预测块开始前，仅用此前已成熟标签训练，冻结该块的树；20个交易日之后向前滚动20日再训练。窗口内每天根据当天可用的滞后因子重新生成信号，不是一次产生20天都相同的仓位。尾部不足20日的预测块按实际长度保存。

### 7.4 对照与扩展实验

P0对照包括STGP的三个单目标滚动策略、FMO Rolling、PRMO Rolling、RMO Rolling和买入持有。P1补充普通GP、非滚动RMO、RSFGP，以及去除dM1至dM5的25因子实验，用于解释类型约束、随机性、滚动机制和市场环境的作用。[P2第9至13、17页]

窗口敏感性使用训练长度60、125、250和预测长度10、20、30的九组组合。至少支持多个随机种子，展示均值、标准差和单次结果；不得只选收益最高的一个种子。论文关于期货7年超额收益84.47%的结论仅作为参考项，不能当作本项目已实现结果。[P2第16页]

## 9 模拟交易前台

### 9.1 主要页面

交易总览展示虚拟资金、净值、累计收益、回撤、持仓与回放时间。行情页展示价格或K线、预测方向、预计持续条目、信号时间和成交标记。策略页展示所用论文、策略版本、训练截止时刻、数据版本、允许交易方向与适用频率。订单与账户页展示委托、成交、手续费、保证金、持仓批次和结算流水。

### 9.2 账户与回放

默认提供可修改的课程虚拟资金，例如100万元，并支持1倍、5倍、20倍回放及逐条推进。回放仅把已到达时间的数据提供给策略和界面；暂停时不推进撮合和账户时间。回放速度影响显示节奏，不影响最终成交与记账结果。

历史回放的自动交易和用户手动交易使用独立会话或独立虚拟账户。同一账户若切换手动与自动模式，需先解决现有挂单和持仓归属；首期默认不允许两个控制源同时驱动同一持仓。重置创建新的会话版本并保留旧记录，便于答辩复查。

### 9.3 策略加载与跨论文关系

发布策略时绑定模型、训练截止、数据模式、参数、成本规则和信号适配器。回放早于模型训练截止时刻的行情会构成未来信息使用，系统必须拒绝，或转入明确的非研究教学演示会话。

首期支持独立加载P1趋势策略或P2遗传规划策略。后续跨论文组合必须先约定标的、频率和时间可用性：例如P2日频策略作为是否允许持多的过滤器，P1五分钟信号负责执行；日频信息只能在实际发布后生效。该组合属于平台新增实验，不是任一论文已有方法。

## 10 回测 撮合与账户规则

### 10.1 统一执行时序

一个行情事件的执行顺序固定为：推进到当前时刻 → 完成此前订单的可执行撮合 → 更新估值与结算 → 读取截至当前已完成行情 → 生成下一时点订单 → 校验并保存。信号时间、委托时间和成交时间分别存储。

默认在某根行情条目收盘后计算信号，在下一根条目开盘成交；只有close字段时改为下一根收盘成交，并显著标明成交口径。禁止使用当前收盘价算出信号后又默认无延迟以同一收盘价成交。若研究原论文理想化同价模式，必须作为单独成本与执行配置报告。

### 10.2 仓位与风控

P1允许目标仓位-1、0、1；P2复现策略允许0、1。同向目标不重复加仓，反向目标平旧开新产生两笔独立成交。非交易时段、数据缺失、资金不足、模型尚未训练完成、输入形状不符和预测非有限值时拒绝新开仓，并记录原因。

止损按多仓或空仓方向计算。只有收盘价时，只能实现收盘触发与下一可成交时点执行的止损；不能声称存在盘中精确止损。存在OHLC时仍需明确根内触发假设。跳空穿过止损价时按实际可成交价格执行，不以阈值价虚构成交。

### 10.3 两种资金口径

论文研究模式用于比较预测策略，使用明确的标准化名义本金与仓位收益，不模拟保证金杠杆。期货账户模式采用实际合约乘数、保证金、费用、逐日结算和风险规则。两种模式分别生成报告，不能把名义本金收益与保证金收益混作同一结果。

期货每笔浮动盈亏按持仓方向、手数、合约乘数与价格差计算；每日结算将结算价相对于上次结算基准的盈亏计入现金并重置基准。权益等于现金与尚未结算盈亏之和，可用资金扣除占用与冻结保证金，费用只在明确的计费事件扣一次。平今与平昨通过持仓批次和开仓交易日区分。

期货账户模式的合约乘数、保证金率、手续费及有效日期来自导入的合约配置，不将论文历史费用当作当前交易所规定。保证金不足触发禁止开仓或按配置强平，强平记录应列入订单和净值。首期至少实现市价委托；限价撮合列为后续功能。

### 10.4 成本与指标

P1历史参考费用为普通开平仓万分之0.23、平今万分之4.6；P2研究参考单边1‰。这两组只作为论文配置展示，不自动用于所有标的和时期。[P1第9页；P2第5、8、14页]

报告分别展示毛收益、手续费、滑点及净收益。滑点以每边点数或基点设定，零滑点必须明示。收益、年化收益、最大回撤、夏普、交易次数、换手、胜率、持仓时间及超额收益统一由后端生成。

夏普默认以每日权益收益计算，年化因子为配置中的年度交易日数，默认252；无风险利率按同频率折算。P2论文以一年期国债为代表，若数据不可得可使用显式0基准并列为差异。收益回撤比的分子声明是累计收益还是年化收益，P2复现默认累计收益；超额收益默认策略累计收益减基准累计收益，并明确单位为百分点。零回撤、零波动时显示不可计算原因。

| REPORT01 | 自动生成复现报告 | 配置、差异、图表、结果、失败实验和参考资料 |

论文方法库中的每一步显示论文节号、PDF页码、对应公式或图表编号、实现模块和验证状态。系统只摘录解释所需的少量内容，以自绘流程和公式实现说明为主，不将论文结果图直接当作自己的实验输出。

### 12.2 存档与版本

每次实验保存完整配置、参数来源、原始文件哈希、数据切分、特征版本、分段版本、代码提交或源码快照哈希、依赖锁文件、设备、随机种子、日志、指标、权重或树及可视化快照索引。没有Git仓库时仍需保存源码快照哈希，不能空置代码版本。

神经网络检查点保存模型参数、优化器状态、epoch、数据加载顺序状态和Python、NumPy、框架随机状态。GP检查点保存种群、树类型、原始指标、当代权重、选择信息、代数、滚动窗口位置和随机状态。

产物先写临时文件，完成后原子重命名并生成校验值。已被报告或策略引用的产物不得被同路径新文件覆盖。删除界面使用归档和引用检查，避免一个清理动作破坏已发布策略。

### 13.2 事件信封

每条事件包含event_id、run_id或session_id、seq、timestamp、type、schema_version和payload。seq在单个运行内单调递增，重连从last_event_id之后补读；前端按event_id去重。训练事件与交易事件各自排序，不假设跨任务存在统一全局顺序。

事件类型至少包含task.state_changed、train.epoch_end、model.snapshot_ready、gp.generation_end、gp.window_end、backtest.progress、signal.created、order.updated、account.updated和task.error。大张量只发送引用、形状、统计及校验值，不把所有值逐batch广播。

## 14 后续论文扩展设计

### 14.1 方法插件契约

每个方法提供元信息、配置schema、步骤schema、输入schema、能力声明及论文映射。算法生命周期统一为validate、prepare、fit、predict、explain、save、load；对于没有训练步骤的方法可以声明无fit能力，不伪造训练进度。步骤schema列出依赖关系、状态和产物，不要求每种方法都经过CNN或LSTM。

能力声明至少包含数据频率、所需字段、是否输出概率、是否输出时长、支持的仓位方向、是否支持断点恢复以及解释类型。解释类型可包括tensor、sequence_state、expression_tree、feature_importance和text；前端通过组件注册表渲染，未知类型使用通用数值或文本视图。

### 14.2 统一输出与策略适配

模型预测结构包含as_of、available_at、symbol、method_version、direction或score、confidence可空、horizon可空、artifact_ref和explanation_ref。策略适配器把预测转换为target_position、effective_from、valid_until及reason_refs，再交给账户风控与执行。

P1适配器读取方向和预计持续时间；P2适配器读取bool并输出0或1。GP不需要伪造duration，纯规则方法不需要伪造confidence。跨频率组合由组合适配器显式对齐可用时间并处理过期信号，不能通过最近日期简单填充未来信号。

### 14.3 增加第三篇论文的步骤

登记资料与复现目标 → 定义输入和配置 → 实现方法接口 → 注册可视化解释类型 → 增加论文到代码的映射 → 编写时序与输出契约测试 → 运行独立对照 → 发布方法版本。只要输出遵循统一信号协议，就能使用现有回测、交易、账户和报告模块。

首期支持开发者以代码注册可信插件。用户上传PDF只建立文献记录，不自动生成可信算法；用户上传的表达式必须经过类型和算子白名单校验。插件升级不能导致旧实验无法加载，应保留旧加载器或提供明确迁移版本。

## 15 实验设计与研究报告

### 15.1 首期实验矩阵

| 实验组 | 最小组合 | 输出证据 |
| --- | --- | --- |
| N1 方向预测 | CNN、LSTM、混合结构；相同切分与种子 | 主损失、分类指标、阈值及混淆矩阵 |
| N2 时长预测 | CNN、LSTM、混合结构 | RMSE、MAE、预测真实散点与误差分布 |
| N3 神经策略 | P1混合、LSTM与买入持有 | 按年度资金曲线、交易清单和成本 |
| G1 GP策略 | 三个单目标及FMO、PRMO、RMO滚动 | 原始三指标、逐代权重与样本外权益 |
| G2 敏感性 | 3×3窗口组合，多种子为P1扩展 | 热力图、均值、波动与参数邻域 |
| X1 平台一致性 | 同一策略同一回放数据两种执行入口 | 回测与会话成交及权益一致 |

### 15.2 结果解释原则

每个对照共享相同数据版本、时间范围、成本、交易规则和调参预算。神经网络与GP频率不同，不能直接把各自最优收益率放在一个排行榜推断算法优劣；比较必须在明示的数据与执行协议下进行。

每份报告包含研究问题、论文依据、数据说明、复现差异、参数、切分图、训练与测试结果、消融与基准、成本口径、交易明细、重复性信息和局限。结果表分为“论文参考值”和“本次实测值”，未运行显示未执行，不显示0或占位收益。

复现成功分为方法结构一致、流程可重复、数值可比较三个层次。没有作者数据或完整细节时，完成前两项仍可形成课程成果；报告应如实解释数值偏差。训练失败、不交易和负收益也属于研究结果，需要保留而非隐藏。

## 16 测试与验收

### 16.1 算法和时间测试

用一条可手算短序列验证分段边界、斜率、时长和双路矩阵。用一个固定样本核对CNN转置、逐层形状与融合相加数值。检查两个混合任务分别使用正确损失，且CNN、LSTM和融合层的参数确实获得梯度并更新。

GP测试覆盖树的输入输出类型、根节点bool、最大深度、受保护除法、交叉变异后的约束；固定一代和三个随机权重，手算多个个体分数，确认所有候选使用相同当代权重且旧精英被重评分。测试同一seed可重现、不同seed能独立记录。

未来信息测试：修改当前回放时间之后的全部价格，已有信号、成交和前缀特征必须不变；若分段端点会重算，也不得更改已冻结的历史输入快照。标签跨界样本、训练截止晚于会话时间、日频信号提前用于五分钟交易等均应被阻断。

### 16.2 交易与恢复测试

用手算价格序列覆盖开多、开空、同向持有、反向换仓、止损、休市、跳空、资金不足、换月和平今平昨费用。每笔账可从上一状态推导下一状态；重复事件不能重复扣费。权益、现金、已实现及未实现盈亏满足记账恒等关系。

相同数据、策略和种子下，1倍与20倍回放得到相同结果；历史回测与模拟自动交易使用相同引擎得到相同成交与净值。中断训练或GP任务后从检查点恢复，在同一支持确定性的设备环境中与不中断结果一致；跨设备差异需说明容差，不宣称绝对位级一致。

### 16.3 可视化与功能验收

| 场景 | 通过条件 |
| --- | --- |
| 修改CNN参数 | 参数校验、形状预览、新实验及差异登记同时生效 |
| 打开真实中间值 | 与所选检查点和样本的后端值在浮点容差内一致 |
| 暂停和恢复 | 到安全边界暂停，继续后轮次或代数连续 |
| SSE断线重连 | 状态可恢复，已处理事件不重复应用 |
| 查看论文依据 | 每个主要步骤能定位论文页码与对应实现 |
| 模型发布与加载 | 不完整产物被拒绝，交易使用发布时绑定的版本 |
| 导出报告 | 包含实测结果、参数、差异与追溯标识 |
| 添加测试方法 | 无需修改撮合和账户代码即可输出可执行信号 |

### 16.4 性能与交付目标

课程参考规模为一个研究者、十万至二十万条行情、一个活动训练任务和一个回放会话。目标是普通查询P95在1秒内、按需单样本解释在2秒内、收到新事件后1秒内刷新界面；启动后记录硬件和实测结果。训练总耗时只做测量与展示，不在未知硬件上承诺固定时长。

界面在桌面浏览器优先支持，图形均提供文字和数值替代信息，不仅靠红绿区分涨跌。训练进程崩溃不拖垮API；磁盘不足、输入错误和非有限损失均显示明确失败原因。网络离线仍能导入本地数据并完成示例训练和回放。
